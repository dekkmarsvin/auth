  `TURNSTILE_SITE_KEY` and public `GET /api/v1/auth/config` with `Cache-Control:

  checker rejects missing/placeholder/test keys and hostnames other than the
  exact Auth iframe hostname `auth.kotoban.top`, without printing env values.
  No wildcard or localhost is permitted by the production checker. The API
  retains upstream wildcard support for separately configured environments.
- Reserve a SHA-256 token hash atomically before Siteverify to prevent both
  sequential and concurrent replays in the single production API process.
  Claims expire after five minutes and the map is capped at 16,384 entries;
  a full guard fails closed. Provider failures release their own claim, while
  success consumes it even when action/hostname checks reject the request.
  No token or secret is stored in the guard. Multiple API replicas would need
  shared consumption state before relying on this additional protection. A
  process restart clears this additional in-memory protection; Cloudflare's
  own validation remains mandatory on every unclaimed token.
- Adapt `a2668c6b` into the existing Build workflow rather than adding duplicate
  upstream CI. Keep pinned pnpm 10.33.4, include every workspace test (including

  startup occurs on `app.use(kit)` or explicit `start()` before router guards.
