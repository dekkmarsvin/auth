## Paired release and rollback

Prepare and validate Auto-Novel Web, Auth Web and Auth API before switching them
in one short authentication maintenance window. Old SDK consumers expect an
iframe login page plus `login_success`; new Auth has independent register/reset
pages. Old/new Turnstile actions also cannot be mixed. Do not maintain a permanent
dual authentication architecture to cover an incomplete release.

Ordinary native login uses the existing credentialed `POST /api/v1/auth/login`
body `{username,password,app}`. Existing JWT/session keys, accounts, passwords and
refresh Cookies do not need migration. Registration/reset return navigation and
OTP action behavior must be verified with the paired versions.

Keep the previous Web/API/Auto-Novel image group for coordinated rollback; do not
roll only the book SDK back to an iframe client while keeping new Auth Web. Reuse
production secrets, PostgreSQL and mounts. Local fixtures do not authorize or
prove production login, CAPTCHA, email, environment changes or deployment.
