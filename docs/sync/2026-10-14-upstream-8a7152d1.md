## Fork adaptations and preserved differences

- Preserve Kotoban Auth/books domains, the fork repository link, existing CORS
  origins, pinned pnpm 10.33.4, portable image ownership, OCI revision labels,
  Docker/Git ignore rules, and the existing frontend/Go/schema/config CI.
- Preserve the runtime public Turnstile configuration endpoint, no-store and
  fail-closed widget behavior, exact production host preflight, bounded SHA-256
  replay protection, Mailgun region/domain settings, PostgreSQL/data mounts,
  legacy penalty schema protections, backup scripts, and ignored personal files.
  These whole-tree differences predate this range; they are not rejected new
  upstream features. The replay guard remains process-local and resets on restart.
- Keep the new WebKit SDK implementation unchanged. Add a small Auth Admin
  adapter outside `packages/web-kit` for its former browser storage keys.
- Migration claims and verifies a persistent
  `auth-admin:web-kit-storage-migration:v1` marker before copying anything.
  Existing new keys take precedence, even if the SDK later rejects their values.
  A valid unexpired legacy session moves from `auth-admin-session` to
  `web-kit:session:v1`; only an administrator can preserve admin mode. The
  former bare `light`/`dark` theme moves from `auth-admin-theme` to the JSON
  preference at `web-kit:theme:v1`.
- Retire legacy keys after the attempt. The marker prevents reimport when logout
  removes the new session, including later writes by an old tab. Marker/storage
  failures do not block startup or import a token without the marker; normal
  SDK cookie refresh and system-theme fallback remain available. Failed copies
  are not retried once the marker is claimed, favoring no token resurrection.
- Combine migration and the upstream theme bootstrap in one head-prepend tag,
  with migration first. The build plugin reads the self-contained migration
  source so configuration bundling cannot leak Function.toString helper names
  into browser execution. Register focused admin tests in the workspace runner.

## Consumer compatibility

- Fixed keys replace `auth.storageKey` and `themeStorageKey`; no upstream
  migration exists. The adapter preserves the fork Admin's applicable values
  without changing WebKit's public API. Browser storage is not server account data.
- `createWebKit` starts immediately; `start` and `dispose` are removed. Resources
  have page lifetime, while the one-instance/one-app installation rule remains.
- Use Whoami predicates instead of removed public `isRoleAtLeast`; use window
  scrolling instead of the removed `useWebKitLayout` scroll context.
- Notify is replaced by Toast. `Toast.promise` resolves undefined on failure,
  so success side effects belong inside the supplied promise's success chain,
  not unconditionally after awaiting Toast. Error messages are formatted without
  mutating the rejected object; the formatter now returns a synchronous string.
- Auto-Novel follows its upstream SDK pin
  `c26edb02b6c64cfac5a0f7b780bfa2c61f9be26a`, not this Auth latest SHA. It remains
  compatible with the existing Auth backend wire contract. Later SDK pin changes
  must account for notification/error APIs rather than assuming SHA parity
  between a client library and the independently deployed Auth service.
